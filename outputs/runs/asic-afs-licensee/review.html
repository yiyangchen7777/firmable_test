怎么审（约 5 分钟）

  1. 看硬指标（校验结果）：有没有 ❌。校验位、枚举、唯一性是代码算的，不会说谎。
  2. 看语义疑点（语义抽检）：这是最需要人的部分——模型挑出「解析没错但含义可能错」的字段，你判断同不同意。
  3. 抽看对照样例（原始 vs 输出）：随手挑两条，问自己「左边这列的意思，真的是右边那个字段吗？」
  4. 扫一眼未映射清单（unmapped）：理由是否诚实，有没有本该映射却被偷懒放弃的列。

你只有三个动作：approve / reject + 意见 / abandon。你不能直接改配置文件——人一改，配置就成了「手写的」，作业的核心主张（agent 独立完成映射）就不成立了。

entity.abnAFS_LIC_ABN_ACN["strip_float_suffix", "digits_only", {"keep_if_length": 11}, "abn_normalize"]0.9conditionalAFS_LIC_ABN_ACN holds values such as '33004739655', '83009199740' and '52089240513', all 11 digits. That is the ABN shape and not the 9-digit ACN shape. The column name says ABN or ACN, so the mapping is gated to 11-digit values and any 9-digit values go to the paired ACN mapping. The licensee is the entity the record is about, so this is the entity's own identifier.

Any 9-digit value such as a stripped-zero ACN would be captured here, and the 11-digit samples ('33004739655', '83009199740') yield no claim. Absence on most rows is intended, so this is the conditional pair of the ABN mapping.

未映射的列 · 5

源列理由
REGISTER_NAMEConstant 'AFS Licence' on every row (1 distinct value). It names the register and describes no entity, so there is no ontology field.
AFS_LIC_NUMThe licence number is the record key, used for record_id. It is not an entity identifier such as ABN, ACN or NZBN, so no ontology field exists.
AFS_LIC_START_DTdd/mm/yyyy dates such as '24/04/2003' and '13/08/2003' (day above 12 confirms day-first) are the licence start date. They are not entity.date_registered, which would be the company's incorporation date, and they are valid_from material, so mapping would be wrong.
AFS_LIC_PRE_FSRHolds the pre-Financial Services Reform licence type and number as a quoted string, e.g. '"Securities dealer","000191662"'. It is a licence relationship attribute with no ontology field, and it is 28.5% null.
AFS_LIC_CONDITIONFree-text licence authorisation or conditions ('This licence authorises the licensee to carry on a financial services business...'). This is licence detail with no ontology field.
