怎么审（约 5 分钟）

  1. 看硬指标（校验结果）：有没有 ❌。校验位、枚举、唯一性是代码算的，不会说谎。
  2. 看语义疑点（语义抽检）：这是最需要人的部分——模型挑出「解析没错但含义可能错」的字段，你判断同不同意。
  3. 抽看对照样例（原始 vs 输出）：随手挑两条，问自己「左边这列的意思，真的是右边那个字段吗？」
  4. 扫一眼未映射清单（unmapped）：理由是否诚实，有没有本该映射却被偷懒放弃的列。

你只有三个动作：approve / reject + 意见 / abandon。你不能直接改配置文件——人一改，配置就成了「手写的」，作业的核心主张（agent 独立完成映射）就不成立了。

未映射的列 · 6

源列理由
REGISTER_NAMEConstant 'BUSINESS NAMES' on every row (1 distinct); it names the register and carries no entity attribute.
BN_REG_DTDate the business name was registered (e.g. 22/10/2019). It is valid_from material for the name claim, which this engine does not yet carry. It is not the holder's registration date, so it would be wrong as entity.date_registered, and it is not observed_at.
BN_CANCEL_DTCancellation date of the business name (86% null, only on Deregistered rows). It is valid_to material for the name claim, which this engine does not yet carry. It is not a per-record extract date, so not observed_at.
BN_STATE_NUMLegacy state-issued business name registration number (e.g. 'BN98583878', 'B2163216W'), 96% null. It is not an ABN or ACN and has no ontology field.
BN_STATE_OF_REGState where the name was originally registered (NSW/VIC/QLD, 96% null), not the holder's address. Mapping it to address.state would be speculative.
BN_STATUSStatus of the business-name registration ('Registered'/'Deregistered'), not of the holder entity. A cancelled name does not mean the holder is deregistered (e.g. a no-ABN row like 'Curry Festival' would wrongly emit entity.status=deregistered). Unmapped per human review and semantic flags.
