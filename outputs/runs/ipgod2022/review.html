怎么审（约 5 分钟）

  1. 看硬指标（校验结果）：有没有 ❌。校验位、枚举、唯一性是代码算的，不会说谎。
  2. 看语义疑点（语义抽检）：这是最需要人的部分——模型挑出「解析没错但含义可能错」的字段，你判断同不同意。
  3. 抽看对照样例（原始 vs 输出）：随手挑两条，问自己「左边这列的意思，真的是右边那个字段吗？」
  4. 扫一眼未映射清单（unmapped）：理由是否诚实，有没有本该映射却被偷懒放弃的列。

你只有三个动作：approve / reject + 意见 / abandon。你不能直接改配置文件——人一改，配置就成了「手写的」，作业的核心主张（agent 独立完成映射）就不成立了。

entity.legal_nameparty_name["trim", "empty_to_null"]0.65Column party_name holds names such as 'davis ip pty ltd', 'exlites pty ltd', 'oculus vr llc'. Semantic spot-checks flagged that many rows are agent, opponent or submitter parties (e.g. opposition_claimant_agent 'krouzer ip', 'fpa patent attorneys', applicant_agent 'davis ip pty ltd'), not the right holder. Each row is still a real party entity on the IP record, and the name is that party's own name, paired with that party's own ABN and address. Because the schema has no role-based entity filter, the claim is kept at reduced confidence. Role columns stay in unmapped. party_type='individual' rows carry only a pseudonymised id (e.g. 'i244880', 'i125033') and give junk name claims, which the catalogue cannot filter.
entity.abnabn["trim", "empty_to_null", "strip_float_suffix", "abn_normalize"]0.8Column abn holds float-serialised 11-digit values such as '53637813471.0' and '35026846389.0'. Checksum pass is 100% (236/236). Semantic flags note that the ABN often sits on agent or submitter rows, so it identifies the named party on that row, which may be an agent firm rather than the right holder. It stays aligned with the party_name on the same row, so the name and ABN pair is consistent. Confidence is lowered for the role ambiguity.
address.statestate_code["trim", "empty_to_null", "state_normalize"]0.9Column state_code holds lowercase Australian state abbreviations ('qld', 'vic', 'nsw', 'wa', 'act', 'sa'), which state_normalize handles case-insensitively. Enum legality is 100%. It is the party's address state, not the IP right's jurisdiction. Blanks are for foreign parties (vg, us).
address.postcodepost_code["trim", "empty_to_null"]0.65Column post_code mixes Australian 4-digit postcodes ('4006', '3000', padded ' 2075 ') with foreign postal codes ('qc, h4t 1k', '443-742', '90404', '315010', '95014'). The keep_if_length 4 gate turned about 15% of non-null values into absence, so conditional pair coverage was only 84.9% (needs >= 95%). The gate and postcode_normalize are removed. The foreign values are genuine postal codes of the party's address (the country sits in country_code), so they are kept as trimmed raw text and every non-null value now yields a claim. Confidence is lowered because the format is no longer uniform. 1xxx PO-box-style postcodes flagged by the spot-check remain a known caveat.
address.countrycountry_code["trim", "empty_to_null"]0.85Column country_code holds lowercase ISO-style codes ('au', 'vg', 'us', 'de', 'jp') sitting alongside the party's state and postcode, so it is the party's address country. It is not the IP right's filing country. Values are kept raw because no country normaliser exists in the catalogue; the case flag is a formatting concern, not a meaning error.
