怎么审（约 5 分钟）

  1. 看硬指标（校验结果）：有没有 ❌。校验位、枚举、唯一性是代码算的，不会说谎。
  2. 看语义疑点（语义抽检）：这是最需要人的部分——模型挑出「解析没错但含义可能错」的字段，你判断同不同意。
  3. 抽看对照样例（原始 vs 输出）：随手挑两条，问自己「左边这列的意思，真的是右边那个字段吗？」
  4. 扫一眼未映射清单（unmapped）：理由是否诚实，有没有本该映射却被偷懒放弃的列。

你只有三个动作：approve / reject + 意见 / abandon。你不能直接改配置文件——人一改，配置就成了「手写的」，作业的核心主张（agent 独立完成映射）就不成立了。

未映射的列 · 10

源列理由
ip_right_typeSingle constant value 'pbr' (plant breeder's rights); describes the type of IP right, not an entity attribute. No ontology field.
application_numberIdentifier of the PBR application (e.g. '1991/079'), not an ABN/ACN/NZBN. Used as record_id only; no entity identifier field.
ip_right_sub_typeConstant 'pbr', duplicating ip_right_type; IP-right classification, no ontology field.
statusValues (terminated, expired, withdrawn, refused, granted) are the lifecycle status of the IP application/right, not of a legal entity. Mapping to entity.status would be semantically wrong, so it is left unmapped.
earliest_filed_dateDate the IP application was first filed (e.g. 1991-08-28), not an entity registration date. Not entity.date_registered.
priority_dateIP priority date, identical to the filing date in the samples; an attribute of the application, not an entity registration date.
gained_registration_status_dateDate the IP right gained registered status (26.5% null); a right-level event, not entity registration. No ontology field.
gained_enforceable_status_dateDate the IP right became enforceable; mirrors gained_registration_status_date. A right-level event, no ontology field.
enforceable_from_dateDate from which the IP right is enforceable, equal to the filing date in the samples; right-level, not entity registration.
deemed_retired_dateDate the IP right was deemed retired (e.g. 1996-01-05); not an entity deregistration or registration date. No ontology field.
