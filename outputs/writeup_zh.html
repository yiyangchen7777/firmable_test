成本 Cost

  • 运行时 API 总花费 $2.83（59 次调用，输入 519k / 输出 180k token，模型 claude-sonnet-5.5，个人 OpenRouter key）。每次调用的步骤、token、金额都记录在 outputs/ledger.jsonl——是账本，不是事后估算。
  • 接入一个源的一次性推断成本：稳态 $0.13–0.55。全新的第七个数据集实测 $0.18（3 次调用、0 轮修订）。第一个源花了 $0.83，因为校准验证器时改了 prompt、缓存失效重计费；磁盘缓存保证崩溃重跑不重复付费。
  • 每条记录的成本：$0——提取是确定性引擎，模型成本不随行数增长。两个超大源按 1000 行播种抽样、一个 6.6 万行源取头部 1000 行、其余全量 → 共 19,542 条标准化 observations。
  • 刻意不计入：搭建系统用的编程助手（个人订阅）。$10 预算管的是系统运行时的花费，两者分开报告。

Agent 设计 Agent design

  • 固定九节点 LangGraph：抓取 → 查看(模型) → 画像(代码) → 提案(模型) → 校验(代码+模型语义抽检) → 修订(模型，≤3 轮) → 审批(人) → 产出。每个节点结束即存 checkpoint，崩溃从断点续跑。
  • 分工铁律：模型提案、代码把关、人拍板。ABN/ACN 校验位、枚举、日期、空值漂移、记录键唯一性全在引擎层强制执行——任何配置都绕不过。数据三切分：200 行给模型看 / 350 行修订循环用 / 150 行验收集只在批准后跑一次，报告只引用后者。
  • 自我修正：校验→修订的边带着失败样例和语义疑点。审批人看到的材料：每条映射的语义证据（列名+样本+为什么是这个含义）、校验结果对阈值、抽检判定、未映射清单及理由、5 组原始行 vs 标准化输出对照。动作只有批准 / 带意见驳回 / 放弃——人永远不直接改配置。七次接入里有五次被审核人驳回过一轮；每次审批事件连同驳回意见原文导出在 outputs/runs/<源>/decisions.json。批准非绿灯状态必须留书面理由（用过一次：源文件自带的重复行）。
  • 最弱环节及其证据：提案节点的语义层。六个源里四个的初版提案把「某登记事项的状态/日期」错配成「企业本身的状态/日期」（牌照状态、商号状态、慈善注册日、IP 权利日期）——每次解析通过率都接近 100%，全靠语义抽检+人工审批抓出来。格式错代码能拦，含义错需要第二次模型审视和人，这就是审批环节存在的理由。
  • Agent 的诚实度实证：喂给它一张拿错的表（植物育种权，没有任何企业），它一个字段都不映射——10 列全部如实弃权，自判 NOT USEFUL（证据保留在 outputs/runs/ipgod2022-wrong-resource-pbr/）。

最难的源 The hard one

ipgod2022（IP Australia 设计权当事人表）。一行 = 一个当事方以某角色（申请人、所有人、代理律所、提交人）出现在一项设计权上；角色列在 ontology 里无处安放；而且源把本地子公司的 ABN 标在外国母公司的行上（原始数据 country_code 为 us/ch）。两个问题都不是改映射能解决的——行过滤被刻意排除在封闭转换目录之外。「什么时候写定制代码是对的」的判断标准：当修复能泛化到所有源、而不是给单一源打补丁时。所以我们没写解析器，而是升级了匹配器（见下一节），对所有源生效。

亚军是折扣名录（完全没有标识符）：在我们的证据门槛下它产生了 0 条被接受的链接——它所有的名字匹配都躺在拒绝队列里、带着理由。那就是我们划的线；队列是交付物，不是失败。

从 6 个源到 500 个 Scale

  • 最先断的是人工审批吞吐量——每源几分钟 × 500 就是一个审核人数周的工作量。解法是按校验状态排队、风险抽样、绿灯批量放行——而不是去掉人。
  • 可达性/反爬虫：我们六选一的候选里就有一个「浏览器能开、脚本全被掐」的站点；triage 需要先探活再打分。
  • 解析分桶与存储：名字桶超线性膨胀；JSONL 让位给数据库、增量运行、记录级 diff。
  • 许可证审查会变成独立工作流（这次运气好全是 CC-BY 系，每条 observation 的信封都记录许可证）。

模型升级问题——在本作业里真实演练过 Change

每条链接记录 matcher_version、run_id、阈值、证据、时间戳；observations 不可变；簇是派生的带版本快照。这让升级可以真做：人工核对 50 条链接测得 matcher-0.1 精确率 62%——19 个错误全是一个模式（外国母公司背着本地 ABN），而且在该源的审批备注里被提前预言过。matcher-0.2 加了一道国别闸，用的是 observations 里本来就带着的国别 claim。

流程：存档 v1 链接 → 重跑 → crosswalk（341 个实体原封不动、0 分裂、13 个收缩或解体：10 全解体 + 3 收缩，正是那批外国母公司簇）→ 用同一套人工标注重新测量：19/19 错误移除、31/31 正确保留。回滚 = 把派生指回 v1 存档。必须提前记录的东西：每链接的匹配器版本+证据+阈值、不可变的 observations（包括当时以为用不上的字段——国别）、带版本的簇快照、一份人工标注样本。

档案组装的数字 Profile assembly

50 份档案来自随机抽样的跨源实体（不挑好看的，种子在代码里）。每字段：胜出值+支持数、两个置信因子分开展示、来源记录、每个落选值及其落选规则；trading_name 按 ontology 多值收集；缺的字段键直接不存在。每份档案带 cluster_support（其下最弱链接的置信度）——因为字段置信建立在「链接正确」的前提上。删一源实验：删掉税务透明度锚点源重跑，50 个实体 31 个解体或消失、19 个幸存、其中 1 个字段值改变——锚点源是单点故障，直接支撑上面的规模答案。

实体关系建模 Entity relationships

存储的真相是成对 same_as 链接表（只追加；撤销用追加记录而不是删除）。实体由 union-find 派生；名字链接可以把记录挂进簇、但永远不能把持有不同 ABN 的两个簇焊在一起；模糊相似永不链接——只进队列。parent_of 类关系有意不碰：声明它们的列进 unmapped 并注明理由，扩展方案是带类型的边（same_as 参与聚簇、parent_of 只存不并）。选「链接为真相」正是因为上面的升级问题：结论（簇 ID）重算起来便宜，证据丢了就没了。
